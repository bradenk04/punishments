# Importing existing punishment history

From the server console, run `/punish import vanilla --dry-run` (or essentials, advancedban, litebans, libertybans). Inspect counts, then rerun without `--dry-run`. The `punishments.import` node is declared; console-only execution is enforced independently. One import may run at a time. Commits are per record: if a source stops halfway, rerun it safely. Imports do not fire live punishment command events.

Configure each source under `imports.<source>` in config.yml. File sources use `directory`; database sources use `url`, `username`, `password`, and a validated alphanumeric/underscore `prefix`. Use a source database account with SELECT-only access. Stop the source plugin and use a copy of an embedded database, so no second process opens its live file. AdvancedBan uses HSQLDB or MySQL; LiteBans uses H2/MySQL; LibertyBans uses HSQLDB/MySQL/MariaDB/PostgreSQL. MySQL JDBC works with compatible MariaDB deployments. Drivers are bundled and isolated.

Vanilla reads `banned-players.json` and counts `banned-ips.json` as skipped. Essentials reads userdata mutes and vanilla ban files in its configured directory; copy vanilla files there if needed. Jails are not imported. Essentials userdata does not preserve original mute issuer/reason/issue time: those unavailable fields stay absent and issue time is the Unix epoch. AdvancedBan imports history and compares active membership; LiteBans imports bans, mutes, warnings and kicks; LibertyBans imports UUID victims through history/active tables. IP and composite/IP-bound punishments are skipped because IP punishments are outside this plugin's scope.

Destination IDs are stable hashes of source + table/original ID (vanilla UUID + creation time; Essentials UUID + mute expiry). Original source ID, issuer name and target name are retained in `punishment_imports`. Known issuer UUIDs, timestamps, reason, expiry and available removal metadata are preserved. Unknown issuer UUIDs use the console/unknown UUID sentinel while the original name remains in provenance. Do not treat that sentinel as a reconstructed account identity. AdvancedBan/LibertyBans do not expose full removal actor/reason/time history in these schemas, so unavailable metadata is not invented.

A dry run validates/parses records and counts destination duplicates without writing punishment, name, provenance or network rows. Successful active imports are immediately visible to database lookups; the network companion enforces them at the next refresh. Always check the failed/skipped counts and test an imported permanent/temporary ban before opening the server to players.

Fixtures cover all five sources, permanent and removed records, source time units and binary UUIDs; repeated runs create no duplicates. Real MySQL/PostgreSQL tests validate destination schemas and repository operations. Source fixtures model the documented schemas; validate a backup from the specific source plugin version before production migration.
