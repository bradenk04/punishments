# Public banlist

Standalone, read-only service. Staff login, revocation and notes remain the follow-up scope explicitly deferred by issue #31.

Build with Go 1.25+: `go mod tidy`, `go test ./...`, `CGO_ENABLED=0 go build -trimpath -o banlist .`.
Or build `docker build -t punishments-banlist web` from the repository root.
CI produces Linux/Windows/macOS binaries and a saved Docker image for distribution; it does not deploy a public server.

Set `DB_DRIVER=mysql` or `DB_DRIVER=postgres` and `DB_DSN` to a database connection string for the shared plugin database. Give the web account SELECT permission only on `punishments` and `punishment_players`. Initialize the tables with the Paper/Velocity plugin first. Keep database credentials in environment variables or a secret manager.

MySQL DSN: `banlist:password@tcp(database:3306)/punishments?timeout=5s&readTimeout=5s&writeTimeout=5s`.
PostgreSQL DSN: `postgres://banlist:password@database:5432/punishments?sslmode=verify-full` (configure a trusted certificate on your deployment).

`PUBLIC_TYPES` defaults to `BAN`; accepted comma-separated types are BAN, MUTE, WARN and KICK. `SHOW_STAFF=true` exposes issuer UUIDs; the default hides staff. `BRANDING` sets the page title. `LISTEN_ADDR` defaults to `127.0.0.1:8080` for the binary; Docker binds the container interface on 8080. Place a TLS reverse proxy in front of any public deployment.

The service queries only an allowlist of fields; no IP or webhook columns are selected. SQL uses parameter binding, escaped name searches, fixed page sizes and request timeouts. Browser rendering uses textContent. API errors omit database diagnostics. No write or staff-auth endpoints are present.

- `GET /api/punishments?search=<name|UUID|ID>&page=0` returns public types, stable pagination and hasMore.
- `GET /api/punishments/<UUID>` returns a public record or 404.
- `GET /api/players/<UUID>?page=0` returns that player's public history.
- `GET /api/config` exposes only branding and public type configuration.

Tests cover hidden staff, secret-free errors, markup escaping, validation and read-only routes. Database integration CI checks both MySQL and PostgreSQL against the tables generated by ORMLite.
